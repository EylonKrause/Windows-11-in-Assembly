# 278 — `RtlIntegerToUnicodeString` — **LANDED** (core ntdll, 5.38× geomean)

Integer formatting in bases 2, 8, 10 and 16. `discovery/rtl_integer_char.c` measured the shipped
export at **32.14 ns** for ten decimal digits, 18.66 for eight hexadecimal, 20.35 for eleven octal,
40.27 for thirty-two binary — **and 10.16 ns for a single digit**.

- **Contract:** `NTSTATUS RtlIntegerToUnicodeString(ULONG value, ULONG base, PUNICODE_STRING out)`.
- **Compared against:** live `ntdll.dll!RtlIntegerToUnicodeString`. **ISA:** baseline x64 — there is
  nothing to vectorise in a number at most thirty-two digits long.

The per-base spread is the tell: thirty-two binary digits costing only twice what ten decimal digits
costs, while **one** digit still costs 10 ns, says the cost is mostly fixed and partly per-digit — a
division loop behind a validation prologue. Change 067 found and fixed exactly that shape, and its
rewritten formatter does a whole 32-bit number in **3.76 ns** against the 12.77 the
division-per-digit version took.

## The contract, measured

`probes/contract.c` asked rather than read, and two of the six answers are not what the
documentation implies.

| | |
|---|---|
| bases accepted | **0, 2, 8, 10, 16 only** — 0 means 10. Every other value 1…0xFFFFFFFF, including 4, 32 and 36, is `STATUS_INVALID_PARAMETER`. The probe asked 0–20 one at a time rather than trusting the documented set, then 36, 256 and 0xFFFFFFFF |
| prefix and case | none, and hexadecimal digits are **uppercase**; zero is `"0"` in every base |
| **the room rule** | **`MaximumLength >= Length + 2`** |
| the terminator | always written, inside `MaximumLength`, and `Length` excludes it |
| on failure | the destination is **completely untouched** — not `Length`, not one character |
| signedness | unsigned: `0xFFFFFFFF` is `"4294967295"`, never `"-1"` |

**The room rule is worth stating loudly.** It is `Length + 2` here — and change 067 found the
analogous rule in `RtlConvertSidToUnicodeString` is **`Length + 1`**, where at exactly `Length + 1`
that routine writes no terminator at all. Two routines in the same DLL, one byte apart, and the only
way to know which is which is to ask each one. Change 067's own gate could not see its rule because
its corpus stepped `MaximumLength` by two; this one sweeps every value.

## Two converters, both length-first

Knowing the length before writing anything is what removes the scratch buffer and the reversal pass a
digit-at-a-time loop needs — change 067's finding, and the reason its rewrite was worth 3.4× on the
number itself.

- **Base 10** is change 067's method: `digits10` from one `BSR`, a byte from a table indexed by the
  bit length, and one compare against a power of ten; then the digits are emitted **two at a time,
  backwards**, as a single dword store from a table of pre-packed UTF-16 pairs, dividing by 100 with
  a multiply. Change 067's `probes/decimal.c` proved `(v * 0x51EB851F) >> 37 == v/100` for **all
  4,294,967,296** values of `v`, and `digits10` exact over the same domain.
- **Bases 2, 8 and 16** share one loop, because they are all powers of two: the shift is `BSR(base)`
  — 1, 3 and 4 — the mask is `base-1`, and the digit count comes from a table indexed by the shift
  and the bit length. One digit per iteration, from the bottom up, straight into the destination.

All five tables are generated by the assembler from the definitions they are supposed to satisfy, and
`correctness.c` checks every one back against those definitions computed the slow obvious way —
change 267's first table construction was wrong.

## Correctness — PASS

Three-way on every case: **ours vs the scalar model in `reference.c` vs the live export**, on the
`NTSTATUS`, `Length`, `MaximumLength` **and every byte of a poison-filled destination** — on failing
calls as well, because a refusal must leave the whole structure alone.

| corpus | cases |
|---|---:|
| 0. the five assembler-generated tables against their definitions | — |
| 1. every base 0–40 plus 256 and 0xFFFFFFFF, including a bad base **and** no room at once | 208 |
| 2. every power of every base, one either side, **every room 0–80** | 11,502 |
| 3. twenty extreme values, five bases, every room 0–80 | 8,100 |
| 4. every value 0–199,999 in all five bases | 1,000,000 |
| 5. the whole 32-bit range on a prime stride, five bases | 81,921 |
| | **1,101,731** |

**0 mismatches**, on the first run. The live export answered `SUCCESS` 1,097,256,
`INVALID_PARAMETER` 183 and `BUFFER_OVERFLOW` 4,292 — the gate fails if any of the three is missing.

Corpus 2 is the one that earns its cost: the length is computed from a `BSR` and a table, so the
values where the answer changes are exactly the powers of the base — and the room rule is decided one
byte at a time, so every `MaximumLength` around each of them is asked.

**Mutation-tested, 9 mutants, all 9 caught** by both gates: base 4 accepted; the room rule moved to
`Length+1`; the terminator not written on the power-of-two path; the base-10 digit-count correction
dropped; the divide-by-100 constant off by one; base 0 meaning 16; `Length` including the terminator;
**a refusal zeroing `Length` on the way out**; and the power-of-two digit table indexed by the base
rather than the shift.

## ABI — PASS

`tools\abi-check\check.bat 278`: all 8 non-volatile GPRs and xmm6–xmm15 preserved, stack balanced,
DF clear. A leaf with **no frame and no calls** — the shape whose unwind data nobody checks because
nothing ever unwinds through it, until something does. The thunk drives **both** converters and both
refusals across seven bases, twelve values and eleven room settings, with sentinels armed per call.

## Live substitution — PASS

`live-substitution\build_int2ustr_live.bat`, **40,000 cases**:

```
[pre-patch]  40000 cases;  SUCCESS 22078 (of which 8856 took base 10, the length-first
             converter, and 13222 a power-of-two base, the shift-and-mask loop),
             INVALID_PARAMETER 5022, BUFFER_OVERFLOW 12900
[patched]    40000 cases, 0 differ;  our-code calls = 40000
[post]       40000 cases through the RESTORED export, 0 differ;  our-code calls = 0
```

Every case compares a hash of the whole destination, and the harness fails if either converter or any
of the three outcomes comes back thin.

**It hung on its first run**, having printed only its header. The corpus draws an illegal base from
`rnd() % 40` one case in seven, and the helper that recomputes how many characters a value needs — so
that `MaximumLength` could be drawn from *around* the boundary rather than from something ample —
divides by that base. `v /= 1` never decreases. The guard is one line and the comment above it says
why.

## Speed — LANDS (no size class regressed)

Fourteen rows, ×8 calls each; every base, both refusals, and the single-digit row that says how much
of the shipped cost is fixed.

| row | ours ns (×8) | ntdll ns (×8) | ratio |
|---|---:|---:|---:|
| base 10, 10 digits | 34.23 | 258.32 | **7.55×** |
| base 10, 1 digit | 16.86 | 80.92 | 4.80× |
| base 16, 8 digits | 31.37 | 150.23 | 4.79× |
| base 16, 1 digit | 15.28 | 78.07 | 5.11× |
| base 8, 11 digits | 40.37 | 161.59 | 4.00× |
| base 2, 32 digits | 85.94 | 318.64 | 3.71× |
| base 10, 4294967295 | 34.92 | 257.18 | 7.37× |
| base 10, zero | 17.31 | 80.55 | 4.65× |
| base 0 (means 10) | 35.49 | 257.01 | 7.24× |
| base 2, all ones | 85.24 | 321.95 | 3.78× |
| base 10, exact room | 34.84 | 257.79 | 7.40× |
| base 16, exact room | 30.91 | 149.97 | 4.85× |
| a refusal: base 7 | 10.22 | 35.14 | 3.44× |
| a refusal: no room | 13.42 | 150.54 | **11.21×** |

**Overall geomean 5.381× over 14 rows. Worst row 3.44×. Every row is BETTER → LANDS.**

Base 10 wins by the most, which is where the length-first two-digit converter is. Base 2 wins least
at 3.71×, because thirty-two digits is thirty-two iterations of the shared loop whatever it is
written in — a nibble table would halve it and is the obvious next thing if this row ever matters.
The "no room" refusal is 11× because the shipped export evidently formats the number before
discovering it does not fit.
