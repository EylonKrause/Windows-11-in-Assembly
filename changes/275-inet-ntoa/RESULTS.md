# 275 — `inet_ntoa` — **LANDED** (ws2_32, 3.24× geomean)

The IPv4 formatter, and the inverse of change 273. `discovery/sid_inet_bstr.c` measured it at
**7.56 ns** for a four-byte address.

- **Contract:** `char* inet_ntoa(struct in_addr in)` — a four-byte struct **by value**, so Win64
  passes it in `ecx` as an integer — returning a pointer into a per-thread buffer.
- **Compared against:** live `ws2_32.dll!inet_ntoa`. **ISA:** baseline x64.
- Works before `WSAStartup`.

## It exists because change 274 asked the same question and got the other answer

Both changes are "our code around an allocation we do not own", and the two were settled the same
way: measure the storage first.

| | change 274 (`SysAllocString`) | **change 275** |
|---|---|---|
| where the answer lives | a BSTR block from oleaut32's private cache | a per-thread buffer |
| can we have our own? | **no** — `SysFreeString` on a hand-made block *terminates the process* | **yes** — it is ordinary TLS |
| the floor we cannot beat | 13.25 ns of allocator | 0.38 ns of TLS access |
| our work inside it | ~0.3 ns of scan | ~1.0 ns of formatting |
| verdict | **PARKED** | **LANDED, 3.24×** |

`probes/floor.c` here did what 274's `probes/where.c` did, before a line of assembly was written:

| | ns per call |
|---|---:|
| `ws2_32!inet_ntoa` | 7.47 |
| C, `wsprintfA` | 22.12 |
| **C, the digit table** — what the assembly does | **1.43** |
| the TLS access alone — the floor | **0.38** |

1.43 against 7.47 with a floor of 0.38 is a real margin. That is the whole justification, and it was
obtained before the file existed rather than after.

## The contract is the buffer

`probes/contract.c` measured what the returned pointer actually is:

| | |
|---|---|
| from one thread | the **same** address on every call — the caller must copy the text |
| from another thread | a **different** address — it is per-thread storage |
| after `inet_addr`, `htonl`, `WSAGetLastError`, `inet_ntop` | **undisturbed** |
| before `WSAStartup` | works, and sets no last error |
| the text | `%u.%u.%u.%u` of the four bytes in memory order — **0 disagreements with `wsprintfA` over all 1024 byte-and-position combinations** |

The probe also caught itself: it asked for the length of `255.255.255.255` and then of `0.0.0.0`,
and printed **7 characters for both** — because they are the same buffer, and by the time the first
`lstrlenA` ran the second call had already overwritten it. That is the contract demonstrating itself,
and it is why both gates copy every answer the instant it comes back.

## One dword store per field

The table holds every value 0–255 already rendered **with its trailing dot**, packed into four
bytes — `"7."`, `"42."`, `"255."` — and a second table holds how far to step. A field costs a table
load, an unaligned four-byte store and an add; the dots come free because they are part of the
rendering, and the fourth one is overwritten with the terminator, which is why the step includes it.

Both tables are generated by the assembler from the definition they are supposed to satisfy, and
`correctness.c` checks them back against it — change 267's first table construction was wrong.

The buffer is 32 bytes for a 16-byte answer: the last store can begin at offset 12 and end at 16, and
`"255.255.255.255"` plus a terminator is exactly 16, so the slack is there to keep that store from
being the thing that decides whether the buffer is big enough.

## Correctness — PASS

Three-way on every case: **ours vs the scalar model in `reference.c` vs the live export**, on the
text. The pointer is deliberately *not* compared — both implementations return a per-thread buffer of
their own, which is exactly what the contract permits.

| corpus | cases |
|---|---:|
| 0. the two assembler-generated tables against their definitions | — |
| 1. every byte value in every position, four backgrounds | 4,096 |
| 2. **all 65,536 combinations of bytes 0–1, and of bytes 2–3** | 131,072 |
| 3. every length transition, all four fields | 10,000 |
| 4. randomised | 400,000 |
| 5. **four threads × 1000 addresses, each checking its own buffer** | 4,000 |
| | **549,168** |

**0 mismatches.**

Corpus 2 is the one that settles it: the formatting is per-byte and the fields are concatenated, so
exhaustive over one byte is not enough and exhaustive over four is 4,294,967,296 pairs of calls. Any
interaction between fields is an interaction between **neighbours**, because the only thing a field
does to the next one is decide where it starts — so exhaustive over adjacent pairs is exhaustive
enough.

**Mutation-tested, 6 mutants, all 6 caught** by both gates: the terminator one byte late; the step
table off by one for three-digit values; two-digit values rendered backwards; the fields in the wrong
order; the last field not advancing the pointer; and **the buffer shared between threads instead of
per-thread** — which only corpus 5 and the live harness's four threads can see.

## ABI — PASS

`tools\abi-check\check.bat 275`: all 8 non-volatile GPRs and xmm6–xmm15 preserved, stack balanced,
DF clear. A 32-byte frame with one register pushed and **one call out**, to the thread-local buffer —
and that call is why the unwind data matters, since a TLS access on a thread whose slot has not been
materialised can unwind. The thunk drives every field length and every mixture, plus all 256 table
entries.

## Live substitution — PASS

`live-substitution\build_inetntoa_live.bat` patches `ws2_32!inet_ntoa`:

```
[pre-patch]  40000 answers recorded from the SHIPPED export;  14795 are 9 characters or
             fewer and 19687 are 14 or more -- the two ends of the step table
[patched]    40000 cases on this thread, 0 differ;  our-code calls = 40000
[patched]    4 threads x 4000 addresses, 0 differ;  our-code calls = 16000
[post]       40000 cases through the RESTORED export, 0 differ;  our-code calls = 0
```

Every answer is copied the instant it comes back — a harness that kept the pointer would compare a
string against whatever the most recent call left there and pass whatever either implementation did.
The four workers are created **after** the patch is in place and joined **before** it is removed, so
no thread is ever inside the sixteen bytes being written.

## Speed — LANDS (no size class regressed)

Eight rows, ×16 calls each: `probes/floor.c` put a call at 1.43 ns and change 261's
`probes/floor.c` put an *empty* call through this harness at 2.32 ns, so a row of one call would
measure the harness and report it as the function.

| row | ours ns (×16) | ws2_32 ns (×16) | ratio |
|---|---:|---:|---:|
| `1.1.1.1` | 35.36 | 116.68 | 3.30× |
| `10.10.10.10` | 35.88 | 116.00 | 3.23× |
| `255.255.255.255` | 35.89 | 116.37 | 3.24× |
| `127.0.0.1` | 35.89 | 115.92 | 3.23× |
| `192.168.168.200` | 35.89 | 115.98 | 3.23× |
| `192.168.1.1` | 35.88 | 116.01 | 3.23× |
| `0.0.0.0` | 35.89 | 115.64 | 3.22× |
| `10.10.2.100` | 35.88 | 115.66 | 3.22× |

**Overall geomean 3.239× over 8 rows. Worst row 3.22×. No size class regressed → LANDS.**

The rows are flat to within 1.5 %, in both columns, which is what this function should look like:
the work is four table loads and four stores whatever the address is, and the only thing that varies
is how far the pointer moves. A row that stood out would mean a data-dependent path that should not
exist.
